# Recurring worker implementation note

## Decision

Add a small `backend/cmd/worker` executable that shares the existing
`RecurringPostgresRepository` with the API. Each tick discovers owners with
active schedules and calls the repository's owner-scoped, bounded `RunDue`
transaction. PostgreSQL remains the source of truth and the occurrence unique
key keeps retries idempotent.

## Configuration

- `WORKER_INTERVAL_SECONDS` controls the loop interval (default `60`).
- `WORKER_ONCE=true` runs one pass and exits for container jobs/cron.

## Verification

Run `go test ./...` and `go build ./cmd/worker`. Runtime DB/UAT evidence is
recorded separately; the worker does not invent report snapshots or bypass
account timezone handling.
