# MyPocket 1.3.1 release plan

Status: approved by owner on 2026-11-06; deployment blocked before production.

## Goal

Publish the latest `main` commit as `prod-1.3.1` with an immutable
multi-platform backend image and promote that digest to `homelab-ops` through
the protected GitOps flow.

## Scope

- Add a release-only backend test gate before the image build.
- Add an app-owned promotion job that updates only the MyPocket ops manifest
  and creates `mypocket-prod-1.3.1`.
- Keep the existing manual migration job for historical/manual recovery; normal
  production deployment is performed by `homelab-ops`.
- Do not change API routes, database data, secrets, or mobile source behavior.

## Required protected inputs

- `REGISTRY_USERNAME` / `REGISTRY_PASSWORD` for the app image push.
- `HOMELAB_OPS_PUSH_TOKEN` and optional `HOMELAB_OPS_REPO_URL` for the
  machine-generated promotion commit.

## Verification

- `go test ./...` and `scripts/mypocket-rollout-preflight.sh` pass before build.
- Build metadata contains an immutable `registry.dungxbuif.com/...@sha256:`
  digest.
- Promotion commit changes only `environments/prod/mypocket.json` and carries
  source tag, source commit, and image digest.
- The ops pipeline owns the production migration, service rollout, health check,
  and rollback evidence.

## Reconciliation after first tag run

- Pipeline `#775` for `prod-1.3.1` was created but failed CI configuration
  validation before any job ran.
- GitLab reported `build job: need test:mypocket-release is not defined in
  current or prior stages`. The included Auto DevOps stage order places
  `build` before the custom `test:mypocket-release`, so the declared DAG was
  invalid even though the job name and rules were correct.
- Remediation: explicitly place the custom release test gate before the image
  build in the project's stage graph, then re-run the same owner-created
  source tag only after CI lint and a new pipeline confirm the DAG is valid.
- Verification must show the test job passes, the build publishes an immutable
  digest, and only then does the promotion job update `homelab-ops`.
- The owner requested a build/delivery-focused pipeline because local tests are
  already covered. The frozen contract still requires one app-owned CI test
  gate, so the compliant reduction is to disable unrelated Auto DevOps test,
  security, and code-intelligence jobs while retaining
  `test:mypocket-release` as the single release gate.
