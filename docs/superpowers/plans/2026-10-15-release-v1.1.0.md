# MyPocket v1.1.0 Release Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** Release the current MyPocket snapshot as semantic version `1.1.0`, deploy the API and worker from an immutable production image, and produce a Release iOS build without changing financial data.

**Architecture:** Version metadata is aligned across the native iOS bundle, web package, and public OpenAPI document. The backend is built once from the release commit, pushed with an immutable `release-1.1.0-*` tag, and the API/worker services are updated to that exact digest. No migration is introduced by this release.

**Tech Stack:** Go, PostgreSQL-backed API/worker, Docker Swarm, React/Vite, SwiftUI/Xcode, XCTest.

**Spec:** `docs/releases/REL-1.1.0-native-ios.md`

## Global Constraints

- Preserve all existing financial data and do not run destructive database commands.
- Do not stage secrets or ignored environment files.
- Production deployment must use one immutable image digest for API and worker.
- A signed physical-device install is only claimed if Xcode provisioning succeeds.
- Public and AI-agent-readable release documentation must describe actual verification evidence and remaining gates.

## Review Focus

- Version metadata must agree (`1.1.0`, iOS build `2`, OpenAPI `1.1.0`).
- API and worker must report the same pushed image digest after deployment.
- Backend, web, and native release gates must be freshly verified.
- Existing production migrations/data must remain untouched.
- iPhone signing failure must be reported as a gate, never presented as a successful install.

### Task 1: Version and release documentation

- [ ] Add the release note and update changelog before implementation.
- [ ] Bump iOS, web, and OpenAPI semantic versions.
- [ ] Reconcile the release note with final test and deployment evidence.

### Task 2: Verification and build

- [ ] Run backend tests/vet, web design/type/build gates, and native guards/tests.
- [ ] Build the release production image from the release commit and deploy API/worker by digest.
- [ ] Build the iOS Release configuration and attempt device signing.

### Task 3: Commit and tag

- [ ] Inspect staged paths for secrets and unrelated generated output.
- [ ] Commit as `release: v1.1.0` and create local tag `v1.1.0`.
