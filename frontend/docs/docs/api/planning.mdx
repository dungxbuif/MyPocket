# Planning API

                type: object

                  events:

      summary: Gắn giao dịch vào sự kiện
      security: [{ cookieAuth: [], csrf: [] }, { bearerAuth: [] }]
components:
  schemas:
    Event:
      type: object
      properties:
        id: { type: string, format: uuid }
        name: { type: string }
        starts_on: { type: string, format: date }

## Obligations (Khoản vay nợ)

```yaml
paths:
  /api/v1/obligations:
    get:
      summary: Danh sách khoản vay nợ
      security: [{ cookieAuth: [], bearerAuth: [] }]
    post:
      summary: Tạo khoản nợ
      security: [{ cookieAuth: [], csrf: [] }, { bearerAuth: [] }]
      requestBody:
        required: true
        content:
          application/json:
            schema: { $ref: "#/components/schemas/CreateObligationInput" }
      responses:
        "201": { description: "Created" }
  /api/v1/obligations/{id}:
    patch:
      summary: Sửa khoản vay/nợ; JSON bắt buộc base_version hiện tại
      security: [{ cookieAuth: [], csrf: [] }, { bearerAuth: [] }]
  /api/v1/obligations/{id}/archive:
    post:
      summary: Lưu trữ khoản vay/nợ; JSON bắt buộc base_version hiện tại
      security: [{ cookieAuth: [], csrf: [] }, { bearerAuth: [] }]
  /api/v1/obligations/{id}/repayments/{transaction_id}:
    post:
      summary: Gắn giao dịch trả nợ
      security: [{ cookieAuth: [], csrf: [] }, { bearerAuth: [] }]
      responses:
        "200": { description: "OK" }
        "400": { description: "Over principal" }
components:
  schemas:
    Obligation:
      type: object
      properties:
        id: { type: string, format: uuid }
        direction: { type: string, enum: ["borrowed", "lent"] }
        principal_vnd: { type: integer }
        counterparty: { type: string }
        due_on: { type: string, format: date }
        note: { type: string }
        repaid_vnd: { type: integer }
        remaining_vnd: { type: integer }
        version: { type: integer }
    CreateObligationInput:
      type: object
      required: [direction, principal_vnd, counterparty, due_on]
      properties:
        direction: { type: string, enum: ["borrowed", "lent"] }
        principal_vnd: { type: integer, minimum: 1 }
        counterparty: { type: string }
        due_on: { type: string, format: date }
        note: { type: string }
```

- `repaid_vnd` = tổng các repayment transactions
- `remaining_vnd` = `principal_vnd - repaid_vnd`
- Overpayment protection: trả về `VALIDATION_FAILED` nếu vượt quá principal
- `direction="borrowed"` chỉ nhận giao dịch `expense`; `direction="lent"` chỉ nhận giao dịch `income`.
- Obligation row được khóa trong lúc kiểm tra tổng repayment và insert link, vì vậy hai request đồng thời không thể cùng vượt principal.
- Một transaction chỉ được tính cho một obligation vì API không có trường phân bổ một phần; link lặp lại cùng obligation là idempotent.

## Transaction Drafts (Bản nháp)

```yaml
paths:
  /api/v1/transaction-drafts:
    get:
      summary: Danh sách bản nháp
      security: [{ cookieAuth: [], bearerAuth: [] }]
  /api/v1/transaction-drafts/{id}/confirm:
    post:
      summary: Xác nhận draft thành đúng một giao dịch
      security: [{ cookieAuth: [], csrf: [] }, { bearerAuth: [] }]
      parameters:
        - name: Idempotency-Key
          in: header
          required: true
          schema: { type: string }
      requestBody:
        required: true
        content:
          application/json:
            schema:
              type: object
              required: [version]
              properties:
                version: { type: integer, minimum: 1 }
                amount_vnd: { type: integer, minimum: 1 }
                note: { type: string }
      responses:
        "200": { description: Confirmed or idempotently replayed }
        "409": { description: VERSION_CONFLICT }
  /api/v1/transaction-drafts/{id}/reject:
    post:
      summary: Từ chối draft mà không đổi số dư
      security: [{ cookieAuth: [], csrf: [] }, { bearerAuth: [] }]
      requestBody:
        required: true
        content:
          application/json:
            schema:
              type: object
              required: [version]
              properties:
                version: { type: integer, minimum: 1 }
      responses:
        "200": { description: Rejected }
        "409": { description: VERSION_CONFLICT }
components:
  schemas:
    TransactionDraft:
      type: object
      properties:
        id: { type: string, format: uuid }
        schedule_id: { type: string, format: uuid }
        occurrence_key: { type: string }
        type: { type: string }
        source_wallet_id: { type: string, format: uuid }
        category_id: { type: string, format: uuid }
        amount_vnd: { type: integer }
        occurred_at: { type: string, format: date-time }
        note: { type: string }
        status: { type: string, enum: ["pending", "confirmed", "rejected"] }
        version: { type: integer }
```

- Drafts do worker sinh ra từ recurring schedules
- `status = "pending"` — chưa được xác nhận
- `confirmed_transaction_id` nullable — khi được confirm
- Không ảnh hưởng balance
- Confirm tạo đúng một finance transaction và áp dụng accounting; gọi lại cùng idempotency key không nhân đôi số dư.
- Reject chuyển trạng thái sang `rejected` và không tạo transaction.

## Optimistic concurrency cho planning

- `PATCH /budgets/{id}`, `PATCH /events/{id}` và `PATCH /obligations/{id}` bắt buộc có `base_version` trong JSON cùng các field cập nhật.
- Các lệnh `/budgets/{id}/archive`, `/events/{id}/archive`, `/obligations/{id}/archive` và `/recurring-schedules/{id}/archive` nhận JSON `{ "base_version": <version hiện tại> }`.
- Thiếu/sai `base_version` trả `400 VALIDATION_FAILED`; version cũ trả `409 VERSION_CONFLICT` và không thay đổi bản ghi.
- Draft confirm/reject dùng field tên `version` (không phải `base_version`) theo contract hiện tại.
